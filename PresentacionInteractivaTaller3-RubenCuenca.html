Análisis de Incidencias Técnicas

Tras auditar events.service.ts, se detectaron fallos críticos que afectan la integridad de los datos y la experiencia del desarrollador.

  • DELETE Ignorado: La acción de borrado se procesa pero nunca llega al save() de TypeORM.
  • Fechas Locales: Uso de toLocaleString() que rompe la estandarización en APIs.
  • Métricas Falsas: El contador de estadísticas ignora el 25% de las acciones (QUERIES).
Mantenimiento Correctivo

Bug: La acción DELETE no persiste

Se identificó un fallo de lógica donde el objeto era creado en memoria pero la llamada al repositorio era inexistente.

events.service.ts — Antes vs Después
- this.deleteRepo.create({ ...dto });
- return { ok: true };
+ const ev = this.deleteRepo.create({ ...dto });
+ await this.deleteRepo.save(ev);

Justificación

Es correctivo porque el sistema fallaba en su promesa fundamental: borrar y registrar el borrado. Corregimos un síntoma de mal funcionamiento inmediato.
Mantenimiento Adaptativo

Estandarización ISO-8601

Migración de formatos de fecha locales a UTC para garantizar compatibilidad con sistemas externos y bases de datos SQL estrictas.

Formateo de fechas
- const date = new Date().toLocaleString(); // "5/5/2026, 10:30 AM"
+ const date = new Date().toISOString();    // "2026-05-05T15:30:00Z"

Justificación

Es adaptativo porque el código no tenía un bug per se, pero su formato lo hacía inútil para la interoperabilidad con otros sistemas modernos que requieren estándares ISO.
Mantenimiento Perfectivo

Optimización de Métricas y Orden

Se añade el conteo de eventos tipo 'QUERY' y se arregla el algoritmo de ordenamiento que fallaba con strings.

getStats() & sort()
+ const queryCount = await this.queryRepo.count();
+ total: create + update + delete + queryCount;
- return a.localeCompare(b);
+ return Date.parse(a) - Date.parse(b);

Justificación

Es perfectivo porque aumenta el valor del sistema. El usuario ahora tiene información más precisa (queries) y mejor presentada (orden cronológico real).
Mantenimiento Preventivo

Blindaje de Entrada (Validators)

Introducción de validaciones de longitud y bloques try-catch para evitar colapsos por payloads malformados.

// Protección proactiva
if (dto.source.length > 100) throw new BadRequestException();
try { ... } catch (err) { logger.error(err); }

Justificación

Es preventivo porque estas medidas no arreglan nada que esté roto hoy, sino que protegen al servidor de ataques de desbordamiento o errores inesperados mañana.
